# 全球招商大会嘉宾工作台使用说明

适用对象：首次接手名单整理、数据核对、部门进展和汇报材料工作的人员。

适用版本：v0.3.0；更新日期：2026年11月23日。

系统地址：https://mcdonaldsqueen.github.io/guest_DataExport_ManageSystem/

## 一、先了解系统的工作方式

本系统把原始Excel中的分散记录，整理为确认参会单位、确认参会嘉宾及相关统计，再导出名单、问题清单和Word核对稿。

完整流程为：上传源表 → 选择工作表和截止时间 → 按规则处理 → 检查处理结果 → 应用到工作台 → 核对资料 → 导出文件与备份。

首次打开没有演示名单，也没有预置真实参会名单。只有应用实际上传的批次后，才会形成业务统计。若当前浏览器已有实际导入的批次，系统会尝试恢复。

数据保存在使用者当前浏览器中。把网页网址发给别人，只会分享系统入口，不会把你的本机名单一并分享。需要交接完整工作进度时，请交接批次备份。

## 二、第一次使用：准备哪些文件

准备一份原始主会场嘉宾填报表，格式为.xlsx，文件不超过20MB。推荐保留完整原始22列表头，包括单位名称、单位简称、国别、单位类型、企业性质1、机构性质2、行业、嘉宾姓名、职务、国籍、邀请单位及是否参加主会场等字段。

系统至少需要同时识别“参会单位名称”“嘉宾姓名”“是否参加主会场”三类表头。只有企业汇总、只有五列嘉宾导出名单或没有参会状态的表格，不能直接替代原始填报表重算。

- 使用.xlsx，不使用旧版.xls或加密文件；可先在Excel中另存为.xlsx。
- 表头应位于工作表前100行；系统兼容表头换行和全半角括号。
- 每张表最多20000行，读取范围最多256列；大文件先拆分整理。
- 公式按Excel中已保存的结果读取，上传前建议在Excel中重算并保存。
- 数据截止时间应由经办人员确认，不要把上传时间自动当作业务截止时间。
- 建议先保存原始文件副本，核对时保留源文件名称和版本。

## 三、导入并形成一个实际批次

1. 打开左侧“数据导入”，点击文件选择框，选中原始.xlsx。
2. 等待读取，检查系统识别出的工作表名称和行数。此时只读取文件，统计还没有切换。
3. 勾选需要参与统计的原始嘉宾表。可以同时选择多张，但不要重复选入同一份名单的副本或另一张重复汇总表。
4. 检查“数据截止时间”，按实际源表填写，例如“2026年11月18日17:57”。
5. 如有已核实的新增名称别名，在“额外名称对照”中填写，每行一条，格式为“原名称=标准名称”；没有则留空。
6. 点击“按规则处理所选表”，等待出现处理结果。
7. 核对确认单位数、确认嘉宾数、待定人数、空白人数、有效原始记录数、归并记录数及排除行数。
8. 结果合理后点击“应用到工作台并替换当前批次”。系统总览、名单、邀请进展、汇报预览和文件导出将使用该批次。

名称对照例子：“某企业旧简称=已核实的企业标准全称”。请把需要合并的多个别名指向同一个标准名称；不能因为关键词相同，就把两个独立法人或不同参会主体合并。

系统传播实际合并单元格中的值，不把未合并的普通空白猜成“跟随上一位嘉宾已确认”。这类空白状态会单列暂计。

应用新批次会替换当前活动批次，并清空上一批次的核对草稿。开始新一轮处理前，先点击“保存当前批次备份”。不要依赖系统保留多个历史批次。

## 四、如何理解确认、暂计和人数

- 状态为“是”：计入确认参会人数。姓名、职务或国籍缺失不会因此扣减人数，缺失信息另列核对事项。
- 姓名为“待定”或空白，但参会状态为“是”：按已确认规则保留人选未落实名额；确认人数不代表所有人选已落实。
- 状态为“待定”：暂按参会保留，单独披露，不计入明确确认人数。
- 状态为空白：有效行暂按参会保留，单独披露，不计入明确确认人数；纯空行和明确模板不计。
- 状态为“否”：不计入参会数。
- 同一嘉宾的来源记录同时存在“是”和“否”：转为待定并列冲突，核实后修改。

含暂计参会人数＝确认人数＋待定暂计人数＋空白暂计人数。剔除待定、空白后的参会人数＝明确为“是”的人数。

单位数不能把三类单位简单相加。一个单位可能同时有“是”的嘉宾和待定嘉宾，系统按对应统计范围对单位去重。

所有数字由实际上传的数据计算，系统没有把1017家或1161人写成固定目标。如果与以前汇报不一致，先检查源文件、截止时间、选中的工作表、名称归并和核对修改。

## 五、企业归并、重复嘉宾及性质分类

企业名称按已核定对照统一，保留原始主体和行号。港澳台企业按中资企业的命名形式展示，不额外拼接外资式国别前缀。集团和子公司是否同一参会主体，需要依据已核实关系判断，不能只凭相似名称自动合并。

同一主体同名嘉宾重复上报，只计1人，全部邀请来源保留。职务兼容时保留更精准表述；职级存在明显冲突时优先区级来源，否则保留较早来源。不同企业中同名嘉宾不会仅凭姓名自动合并。

同企业由不同部门填报的匿名名额按规则归并，不按部门数简单累加；同一部门内明确多行名额会保留。无法确认是否不同名额时，应根据原始行号与邀请部门核实。

企业看性质1，机构看性质2。企业多项性质按编号从小到大选唯一主分类：1世界500强外企、2世界500强国内企业、3中国民营企业500强、4外资企业、5央企、6上市公司、7独角兽、8国企、9民营企业、10其他。

世界500强使用2025、2026两年榜单并集；“中国500强”指中国民营企业500强。原表写了500强不等于已经核实上榜，集团标签承接应有已核定关系。主分类统计与多标签统计含义不同，不要混用加总。

## 六、信息核对：修改嘉宾和单位

进入“信息核对”，可筛选人选未落实、职务缺失、国籍缺失、参会状态待确认或单位问题。默认显示未查看记录，也可切换已查看和全部问题。

1. 点击“开始核对”或嘉宾页的“查看／核对”，查看邀请来源、原始行号和原始姓名、职务。
2. 根据业务方确认结果修改姓名、职务、国籍或地区身份、参会状态。
3. 填写“核对依据／说明”，例如核对渠道与结论；点击保存。
4. 返回总览或名单检查人数和相关标签；参会状态影响确认数，职务影响处理批次的高管与重点筛选。
5. 修改错误时，可在嘉宾抽屉中恢复该条原始数据。

“仅标记已查看”只是记录你已审阅，不会补齐缺失值，也不会把待定自动改为“是”。一条记录可能有多个问题，问题分项人数不能直接相加。

在“参会单位”点击“查看明细”，下方可核对单位标准名称、简称、国别、类型、性质和行业，填写依据后保存。原始Excel不会被直接改写。

修改单位展示名称不会自动合并两个单位；修改嘉宾姓名也不会自动再次进行身份去重。需要改变归并关系时，应修正源表或导入名称对照，然后重新处理并应用新批次。

## 七、各个页面分别用来做什么

- 工作总览：查看确认单位、确认嘉宾、重点嘉宾、待完善资料、行业分布及含暂计／剔除暂计两套结果。
- 数据导入：读取原始Excel、选择工作表、处理和应用批次，保存或恢复JSON备份。
- 信息核对：集中处理缺失和冲突，记录核对依据及查看状态。
- 参会单位：搜索、筛选确认单位，查看类型、性质、行业、嘉宾及邀请来源。
- 参会嘉宾：查看确认嘉宾，可筛选重点、高管或资料待完善记录。
- 邀请进展：切换各区和市直单位，查看指标、确认单位、其中企业、确认嘉宾及完成率。
- 文件输出：生成名单Excel、问题清单和Word核对稿。
- 统计规则：查看当前载入的规则文字。业务规则变更应先同步规则文件，再更新程序；本页不提供在线编辑规则。

## 八、重点嘉宾、高管和国籍地区如何看

重点嘉宾须为确认参会，企业全称、简称、类型／性质、姓名、职务五项完整。排序仍为A榜单企业、B其他企业、C机构；集团负责人和中国区一把手同层，明确下属参会主体负责人随后。

新版按实际职级和范围筛选：央国企总经理、党委负责人及相应副职，外企全球／集团主席和中国区整体经营负责人，专业服务或投资企业符合条件的管理、执行、首席、高级合伙人可以结合性质、主体及范围纳入。央国企识别保留全部性质标签，不只看主分类。

纯创始人、联合创始人、裸合伙人或范围不清的主席先列“重点候选待核对”。创始人头衔不能证明企业是初创或本人目前仍经营；部门总经理、市场或政府事务负责人不能直接等同企业或中国区一把手。

在“参会嘉宾”筛选“重点候选待核对”，查看依据和原因。打开嘉宾详情，下方“重点筛选核实”可选择自动、待核对、纳入或排除。纳入需填写业务依据，确认当前参与经营／决策，明确集团、中国区或本参会主体范围；五项完整、确认状态和榜单核验条件仍须满足。

需要修订姓名、职务、该条企业简称时，先保存上方嘉宾资料，再核实。职务或单位主体／性质变化后，原重点核实失效。恢复嘉宾原始数据清除该人工重点核实。核实依据、范围、结论及日志保存在本机批次与JSON备份中。

文件输出新增“重点候选Excel”和“重点筛选依据Excel”，附层级、范围、识别依据、待核对原因、人工依据、邀请来源和原始行号。候选不计正式重点人数；原高管口径不因重点范围扩展而增加。

高管按董事长、总裁、副总裁、CEO等明确关键词识别，排除助理、秘书和办公室等表述。不是所有总经理都默认计作副总裁以上。人选待定但符合职务、参会为“是”的名额按规则保留。

嘉宾中国香港、中国澳门、中国台湾身份单列，不计外籍；空白或待定列未知。企业国别不用于补嘉宾国籍。单位国别填中国也不能单独据此断定为内资企业。

## 九、邀请进展与完成率

在“邀请进展”切换“各区级单位”和“市直单位”，按确认单位数查看排名，可调整升降序并导出进展Excel。

完成率＝本部门确认参会单位数÷任务指标。深汕特别合作区、大鹏新区为50家，其余已列区级单位为100家；市直单位使用已配置的各单位指标。

“确认单位”包含企业和招商合作机构；“其中企业”另列。不要把其中企业数误作全部确认单位数，也不要擅自更换完成率分子。

同一企业可能被多个部门邀请，各部门可分别计算成果；部门内部去重。因此部门成果加总可能大于全市去重总数，这不必然意味着计算错误。

## 十、生成Excel和Word

进入“文件输出”，按需要点击生成。确认单位和确认嘉宾分别输出，重点嘉宾、高管也各自独立输出Excel。

- 确认单位名单：企业全称、简称、单位类型、企业性质、机构性质、行业、确认嘉宾人数、邀请来源。
- 确认嘉宾名单：企业全称、企业简称、企业类型、嘉宾姓名、嘉宾职务。
- 重点嘉宾名单：上述五字段，按榜单企业、其他企业、机构重点顺序输出。
- 总裁及副总裁以上明细：上述五字段，使用当前确认批次职务筛选。
- 待核对清单：企业、嘉宾、参会状态、问题、邀请来源、原始行号。可每日导出发给业务方确认。
- 邀请进展：在邀请进展页导出，包含指标、确认单位、其中企业、嘉宾和完成率。
- Word核对稿：同一批次统计、暂计披露、嘉宾国籍地区及各部门进展；也可先复制预览文字。

文件生成后由浏览器保存到其下载目录。若没有弹出保存框，检查浏览器下载列表和默认下载文件夹。Excel、Word不是完整工作进度备份；迁移系统请使用JSON备份。

正式汇报前，检查数据截止时间、源文件、口径和明细能否相互对应。Word是核对稿，企业列举、重点嘉宾事例和正式公文措辞仍需业务审核。请用桌面Excel、Word检查最终文件和打印排版。

## 十一、保存、恢复和交接工作

日常核对修改会保存到当前浏览器，刷新后尝试恢复。清理浏览器数据、隐私模式结束、换设备或换浏览器，都可能影响本机记录。每次完成一轮核对后，建议另存批次备份。

保存：进入“数据导入” → 点击“保存当前批次备份” → 保存生成的.json文件。建议自行按日期、截止时间和经办人重命名，并保留对应原始.xlsx。

恢复：新接手人员打开同一系统 → 进入“数据导入” → 在“恢复批次备份”处选择.json → 系统恢复该批次的原始记录、处理结果、核对草稿及日志。恢复会替换当前活动工作进度，请先备份现有批次。

建议交接四样材料：原始Excel、最新JSON批次备份、已报送的Excel／Word文件、仍待确认的问题清单。交接时说明数据截止时间、核对进度和采用的规则版本。

目前没有多人实时同步。两个人分别修改自己的副本不会自动合并，建议约定一个主经办人维护正式批次，其他人员按问题清单反馈。不要将真实名单或批次备份上传到公开GitHub仓库。

## 十二、常见问题

### 上传后为什么统计还没变？

读取、处理和应用是三个步骤。读取后先检查工作表，点击按规则处理；出现结果后还要点击“应用到工作台并替换当前批次”。

### 提示没有识别到必要表头？

确认文件是原始嘉宾填报表，包含单位名称、嘉宾姓名和是否参加主会场，表头在前100行。仅有单位名单或五列导出名单不能重算；请补回原始字段，或恢复完整JSON备份。

### 为什么人数比原表行数少？

可能排除了模板、说明行，合并了重复嘉宾、重复匿名名额，或剔除了否、待定和空白。对照处理摘要、邀请来源和原始行号核查，不要直接把原表行数当确认人数。

### 为什么确认名单还有待定姓名或空缺职务？

参会状态“是”决定确认计数，资料完整度另算。人选未落实名额按已确认规则保留，需通过问题清单继续核实。

### 为什么重点嘉宾数比高管数少，或两者不一致？

两者筛选条件不同。重点还要求五项完整并核对榜单、职务范围；高管按明确职务关键词识别。机构一把手也可进入机构重点，因此重点与高管不是完全包含关系。

### 为什么部门合计比全市单位数多？

同一企业的多个邀请部门分别计成果，全市只去重计一次。使用部门加总时应明确注明含跨部门重复成果。

### 换电脑后为什么是空工作台？

数据保存在原浏览器，不在共享服务器。请在原设备导出JSON批次备份，再到新设备恢复。

### 网站更新后仍显示旧内容怎么办？

按Ctrl＋F5刷新。系统不再预置演示名单；实际导入的本机批次会保留。不要为了刷新网页先清理全部浏览器数据，以免丢失未备份的工作。

### 提示本机保存失败怎么办？

先不要关闭页面，立即导出JSON备份和需要的名单。当前页面仍可查看和导出，重新打开或刷新前先确保备份文件保存成功。

### Excel提示修复或文件打不开怎么办？

先确认文件完整保存、扩展名正确，再重新生成。仍异常时保留出错文件、原始输入及操作步骤，反馈具体文件类型和Excel错误提示；不要把“自动修复成功”直接当成已正式验证。

## 十三、建议的每日操作顺序

1. 备份上一批次，归档昨天的报送文件和待核对清单。
2. 确认今天的源文件版本、截止时间及新增业务确认信息。
3. 导入并处理，检查数量变化和明显异常，再应用新批次。
4. 核对参会状态、人选、职务、国籍、单位性质及归并关系。
5. 导出待核对清单，跟进邀请部门反馈；“已查看”不等于问题已解决。
6. 生成名单和Word，核查确认口径与含暂计口径的表述。
7. 保存最新JSON备份，并与原始Excel、最终报送件一起交接归档。

## 十四、系统能力边界

当前支持本机导入、规则处理、核对、统计、导出及备份恢复。尚不支持账号权限、多人实时协作、服务端正式批次审签、自动合并多人草稿和完整历史批次库。

系统自动处理已明确的字典和规则，不能替业务方确认参会意愿、任职真实性或存在歧义的企业关系。正式报送前，应由经办人员完成业务核实和文件复核。
