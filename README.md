# 嘉宾名单核对、统计与导出工作台

**v0.3.0 · 浏览器本机处理版**

在线使用：https://mcdonaldsqueen.github.io/guest_DataExport_ManageSystem/

将原始主会场Excel按统一规则处理，生成确认单位、嘉宾、重点嘉宾、高管、问题清单、邀请进展及Word核对稿。首次打开为空工作台，不预置任何参会单位或嘉宾。用户上传的真实名单在本机浏览器解析和保存，不上传GitHub或其他业务服务器。公开企业名称对照和榜单不包含真实嘉宾、联系人或参会状态。

## 使用流程

1. 进入“数据导入”，选择20MB以内的原始.xlsx。
2. 检查识别的原始嘉宾工作表，填写源表对应的数据截止时间。不要将同一名单的副本重复选入。
3. 有已确认名称对照时逐行填“原名称=标准名称”，不要仅凭关键词合并不同独立主体。
4. 点击“按规则处理所选表”，检查确认、待定、空白及排除项。
5. 点击“应用到工作台并替换当前批次”，全部统计、名单及导出才会切换。
6. 在信息核对和单位详情修订资料、填写依据，职务修改联动高管和重点标签。
7. 在文件输出生成独立Excel或Word。导入页提供完整JSON批次备份与恢复。

1017家、1161人不是程序写死的目标，实际结果取决于上传文件与名称对照。

## 统计口径

| 项目 | 规则 |
| --- | --- |
| 确认 | 状态“是”计入；姓名、职务、国籍缺失不扣人数，另列问题 |
| 暂计 | 有效行的待定、空白分别披露；含暂计总数纳入，确认口径剔除 |
| 不参会 | “否”不计入；同人“是/否”冲突转待定核对 |
| 企业 | 核定名称对照归并，集团、品牌和法人不凭关键词混并 |
| 嘉宾 | 同企业同名计1人，兼容职务保留精准表述，职级冲突优先区级来源，否则较早来源；保留全部邀请来源 |
| 匿名名额 | 同企业跨部门匿名名额合并；同部门多行名额保留，不按不同部门简单累加 |
| 性质 | 企业看性质1、机构看性质2；多性质按编号从小到大择唯一主分类 |
| 世界500强 | 2025或2026上榜即可，已核定集团对照允许承接；原表标签不独立作为榜单证据 |
| 中国500强 | 指中国民营企业500强，按提供的榜单核验 |
| 国别 | 城市映射中国；嘉宾港澳台单列、不计外籍；不用企业国别补嘉宾国籍 |
| 行业 | 30项标准及已明确同义映射；歧义待核对，不强行归其他 |
| 邀请成果 | 部门内去重、跨部门分别计成果，加总不等于全市去重数 |
| 完成率 | 确认单位÷任务；深汕、大鹏50，其余所列区级单位100，市直按配置 |

## 重点嘉宾与高管

重点嘉宾须为确认参会，企业全称、简称、类型／性质、姓名、职务五项完整。排序仍为A榜单企业、B其他企业、C机构；集团负责人和中国区一把手同层，明确下属参会主体负责人随后。

新版按实际职级和范围筛选：央国企总经理、党委负责人及相应副职，外企全球／集团主席和中国区整体经营负责人，专业服务或投资企业符合条件的管理、执行、首席、高级合伙人可以结合性质、主体及范围纳入。央国企识别保留全部性质标签，不只看主分类。

纯创始人、联合创始人、裸合伙人或范围不清的主席先列“重点候选待核对”。创始人头衔不能证明企业是初创或本人目前仍经营；部门总经理、市场或政府事务负责人不能直接等同企业或中国区一把手。

在“参会嘉宾”筛选“重点候选待核对”，查看依据和原因。打开嘉宾详情，下方“重点筛选核实”可选择自动、待核对、纳入或排除。纳入需填写业务依据，确认当前参与经营／决策，明确集团、中国区或本参会主体范围；五项完整、确认状态和榜单核验条件仍须满足。

需要修订姓名、职务、该条企业简称时，先保存上方嘉宾资料，再核实。职务或单位主体／性质变化后，原重点核实失效。恢复嘉宾原始数据清除该人工重点核实。核实依据、范围、结论及日志保存在本机批次与JSON备份中。

文件输出新增“重点候选Excel”和“重点筛选依据Excel”，附层级、范围、识别依据、待核对原因、人工依据、邀请来源和原始行号。候选不计正式重点人数；原高管口径不因重点范围扩展而增加。

详见[重点嘉宾确认规则](docs/重点嘉宾确认规则.md)、[统计影响](docs/统计口径影响说明.md)与[个案核对](docs/规则待确认问题.md)。旧批次打开及恢复时自动重算重点标签，原始Excel不变。

## 输入及导出

表头可在前100行，兼容换行和全半角括号，必须同时具备单位名称、嘉宾姓名、是否参加主会场。推荐完整原始22列。仅传播实际合并单元格，不把普通空白视作跟随上一行。重复表头、明确模板和说明行排除。

每表最多20000行、256列，超行数直接提示。支持共享/内嵌字符串、工作表名、原始行号及合并区域。不支持旧.xls、加密文件、宏运行或公式重算；公式使用已保存缓存值。展开后的XML有大小上限。

| 输出 | 字段或用途 |
| --- | --- |
| 确认单位Excel | 全称、简称、类型、性质、行业、嘉宾数、邀请来源 |
| 确认嘉宾/重点/高管Excel | 企业全称、简称、类型、姓名、职务；重点按A/B/C排序 |
| 问题清单Excel | 企业、嘉宾、状态、问题、邀请来源、原行号 |
| 邀请进展Excel | 指标、确认单位、其中企业、嘉宾、完成率 |
| Word核对稿 | 同批次单位/嘉宾、暂计、国籍地区、部门进展 |
| JSON备份 | 完整批次、原始记录、草稿及日志，可恢复 |

Word为核对稿，正式公文企业列举和重点事例需据确认名单另行审核。Office自动检查ZIP和XML合法性，正式报送前请用桌面Office检查排版。

## 保存与多人使用

活动批次、源记录、草稿及日志保存到当前浏览器IndexedDB，刷新后尝试恢复。新批次替换旧批次并清空旧草稿，请先备份。保存失败会提示，当前页面可继续导出。JSON备份含真实名单，请自行妥善保管。

清理浏览器数据、隐私模式结束、换设备会影响本机数据；用备份迁移。v0.1草稿不自动套入新批次；浏览器曾保存的旧演示批次自动忽略，实际导入的本机批次保留。公开网址可由不同使用者各自导入，不提供多人同步、登录、权限或服务端审签。不要把真实名单替换进公开data.json。

修改单位展示名称不会自动合并主体，修改姓名不会再次去重；需要身份归并时请更正源表或名称对照重新处理。单位修改保存核对依据，原始Excel不变。

## 开发、文件结构与部署

Node.js 20+，Office验证需要Python 3，无需npm依赖和打包器。运行npm start启动静态服务，npm test运行测试，python scripts/check_office.py校验Office，npm run build校验静态资源。不能用file://直接打开。

| 文件 | 作用 |
| --- | --- |
| dist/app.js | 界面、搜索、抽屉及导出 |
| dist/integration.js | 导入、应用、本机保存、核对联动、备份恢复 |
| dist/processing.js | 表头、清洗、去重、分类与标签；API为Processing.create(config)返回parseSheets/fromRecords/screen |
| dist/processing-rules.json | 行业、性质、核定名称对照、两年世界榜单及民营榜单 |
| dist/xlsx-reader.js | XLSX解析，保留工作表、行号、真实合并区域 |
| dist/office.js | OOXML导出 |
| dist/vendor/ | JSZip、SAX和各自许可证 |
| dist/data.json | 空名单及部门、规则配置 |
| tests/ | 页面快照与处理流程回归 |
| scripts/ | 静态服务器、资源验证、Office校验 |

GitHub仓库Settings → Pages → Build and deployment → Source选择GitHub Actions。main分支dist、脚本、测试或工作流改动触发自动部署，验证和部署成功后打开公开网址；必要时Ctrl+F5刷新。详情见[数据契约](docs/DATA_CONTRACT.md)。[v0.1历史说明](docs/V0.1-ARCHIVE.md)只供参考，其中仅预览等限制已被本版替代。
